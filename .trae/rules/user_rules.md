# 个人开发规则配置

## 系统环境
- **操作系统**: Windows

## 前端开发规范

### 调试规则
- **npm服务管理**: 调试前端代码时不要重启npm服务，保持服务持续运行以提高开发效率

### 代码组织
- **文件分离**: 前端页面的CSS、JS、HTML必须分开编写，不能写到一个文件里
- **通用CSS**: 建立通用CSS概念，提取公共样式到独立文件，避免重复代码
  - 创建 `styles/common.css` 或类似文件存放通用样式
  - 使用CSS变量定义主题色、字体等全局配置
  - 组件特定样式应放在组件目录下的独立CSS文件中

### 数据问题排查流程
当排查前端数据问题时，必须按以下顺序逐层测试：

1. **前端层**
   - 检查前端组件是否正确接收和渲染数据
   - 验证数据绑定和状态管理是否正确
   - 使用浏览器开发者工具检查网络请求和响应

2. **API层**
   - 检查API接口是否正确调用
   - 验证请求参数是否正确传递
   - 使用Postman或类似工具测试API接口

3. **底层代码层**
   - 检查后端业务逻辑是否正确处理数据
   - 验证数据转换和格式化逻辑
   - 检查中间件和拦截器是否正常工作

4. **数据库层**
   - 检查数据库查询语句是否正确
   - 验证数据是否正确存储和检索
   - 检查数据库连接和事务处理

### 代码注释规范
- **函数级注释**: 所有函数必须添加函数级注释，说明：
  - 函数功能描述
  - 参数说明（类型、含义）
  - 返回值说明（类型、含义）
  - 异常情况说明（如有）

```javascript
 */

  // 实现代码
}
```

## 注意事项
- 遵循以上规则可以提高开发效率和代码质量
- 在团队协作时，这些规则有助于保持代码一致性
- 定期回顾和更新规则以适应项目需求变化
