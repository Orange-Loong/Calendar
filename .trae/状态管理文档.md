# 电子日历状态管理文档

## 一、状态管理方案选择

### 1. 技术选型

| 平台 | 状态管理方案 | 选择理由 |
|------|--------------|----------|
| Web端 | React Context API + useReducer | 适合中小型应用，无需额外依赖，React内置，易于学习和使用 |
| 移动端 | React Context API + useReducer | 与Web端保持一致，简化跨平台开发，性能满足需求 |

### 2. 备选方案对比

| 方案 | 优点 | 缺点 |
|------|------|------|
| Redux Toolkit | 强大的状态管理能力，良好的调试工具，适合大型应用 | 学习曲线较陡，样板代码较多 |
| Zustand | 轻量级，易于使用，性能优秀 | 生态相对较小，适合中小型应用 |
| Jotai | 原子化设计，灵活，性能优秀 | 概念较新，学习成本较高 |

### 2. 状态切片详细设计

#### 2.1 认证状态 (auth)

| 字段 | 类型 | 描述 |
|------|------|------|
| isAuthenticated | boolean | 用户是否已认证 |
| user | object | 用户信息对象 |
| token | string | JWT令牌 |
| loading | boolean | 认证请求是否正在进行 |
| error | string | 认证错误信息 |

#### 2.2 日历状态 (calendar)

| 字段 | 类型 | 描述 |
|------|------|------|
| currentView | string | 当前日历视图（day, week, month） |
| currentDate | Date | 当前显示的日期 |
| selectedDate | Date | 用户选中的日期 |
| isLoading | boolean | 日历数据是否正在加载 |
| error | string | 日历数据加载错误信息 |

#### 2.3 日程状态 (events)

| 字段 | 类型 | 描述 |
|------|------|------|
| items | array | 日程列表 |
| isLoading | boolean | 日程数据是否正在加载 |
| error | string | 日程数据加载错误信息 |
| selectedEvent | object | 当前选中的日程 |

#### 2.4 任务状态 (tasks)

| 字段 | 类型 | 描述 |
|------|------|------|
| items | array | 任务列表 |
| isLoading | boolean | 任务数据是否正在加载 |
| error | string | 任务数据加载错误信息 |
| filter | string | 任务筛选条件（all, completed, incomplete） |
| sortBy | string | 任务排序方式（dueDate, createdAt, priority） |

#### 2.5 家庭状态 (family)

| 字段 | 类型 | 描述 |
|------|------|------|
| currentFamily | object | 当前家庭组信息 |
| members | array | 家庭成员列表 |
| isLoading | boolean | 家庭数据是否正在加载 |
| error | string | 家庭数据加载错误信息 |

#### 2.6 积分状态 (points)

| 字段 | 类型 | 描述 |
|------|------|------|
| userPoints | object | 用户积分信息，包含总积分、每日获取积分和每日上限 |
| transactions | array | 积分交易记录列表 |
| isLoading | boolean | 积分数据是否正在加载 |
| error | string | 积分数据加载错误信息 |
| showRedeemForm | boolean | 是否显示积分兑换表单 |

const authReducer = (state, action) => {
  switch (action.type) {
    case 'auth/LOGIN_REQUEST':
    case 'auth/REGISTER_REQUEST':
    case 'auth/UPDATE_USER_REQUEST':
      return {
        ...state,
        loading: true,
        error: null
      };
    
    case 'auth/LOGIN_SUCCESS':
    case 'auth/REGISTER_SUCCESS':
      return {
        ...state,
        isAuthenticated: true,
        user: action.payload.user,
        token: action.payload.token,
        loading: false,
        error: null
      };
    
    case 'auth/LOGIN_FAILURE':
    case 'auth/REGISTER_FAILURE':
    case 'auth/UPDATE_USER_FAILURE':
      return {
        ...state,
        loading: false,
        error: action.payload
      };
    
    case 'auth/UPDATE_USER_SUCCESS':
      return {
        ...state,
        user: { ...state.user, ...action.payload },
        loading: false,
        error: null
      };
    
    case 'auth/LOGOUT':
      return {
        ...state,
        isAuthenticated: false,
        user: null,
        token: null,
        error: null
      };
    
    default:
      return state;
  }
};

## 四、Context 设计

### 1. 创建 Context

```javascript
import React, { createContext, useContext, useReducer, useEffect } from 'react';
import AsyncStorage from '@react-native-async-storage/async-storage';

// 创建 Context
const AppContext = createContext();

// 创建 Provider 组件
export const AppProvider = ({ children }) => {
  // 初始化状态
  const [state, dispatch] = useReducer(rootReducer, initialState);
  
  // 加载持久化数据
  useEffect(() => {
    const loadPersistedData = async () => {
      try {
        // 从 AsyncStorage 加载数据
        const persistedAuth = await AsyncStorage.getItem('auth');
        if (persistedAuth) {
          const authData = JSON.parse(persistedAuth);
          dispatch({ type: 'auth/LOGIN_SUCCESS', payload: authData });
        }
      } catch (error) {
        console.error('Failed to load persisted data:', error);
      }
    };
    
    loadPersistedData();
  }, []);
  
  // 持久化认证状态
  useEffect(() => {
    const persistAuth = async () => {
      try {
        if (state.auth.isAuthenticated) {
          await AsyncStorage.setItem('auth', JSON.stringify({
            user: state.auth.user,
            token: state.auth.token
          }));
        } else {
          await AsyncStorage.removeItem('auth');
        }
      } catch (error) {
        console.error('Failed to persist auth data:', error);
      }
    };
    
    persistAuth();
  }, [state.auth.isAuthenticated, state.auth.user, state.auth.token]);
  
  return (
    <AppContext.Provider value={{ state, dispatch }}>
      {children}
    </AppContext.Provider>
  );
};

// 自定义 Hook，方便组件使用 Context
export const useAppContext = () => {
  const context = useContext(AppContext);
  if (!context) {
    throw new Error('useAppContext must be used within an AppProvider');
  }
  return context;
};
```

### 3. 异步操作（使用自定义 Hook）

```javascript
import { useCallback } from 'react';
import { useAppContext } from '../contexts/AppContext';
import { api } from '../services/api';

export const useEventActions = () => {
  const { dispatch } = useAppContext();
  
  // 获取日程列表
  const fetchEvents = useCallback(async (date) => {
    dispatch({ type: 'events/FETCH_EVENTS_REQUEST' });
    try {
      const response = await api.get(`/events/${date.toISOString().split('T')[0]}`);
      dispatch({ 
        type: 'events/FETCH_EVENTS_SUCCESS', 
        payload: response.data 
      });
    } catch (error) {
      dispatch({ 
        type: 'events/FETCH_EVENTS_FAILURE', 
        payload: error.message 
      });
    }
  }, [dispatch]);
  
  // 创建日程
  const createEvent = useCallback(async (eventData) => {
    dispatch({ type: 'events/CREATE_EVENT_REQUEST' });
    try {
      const response = await api.post('/events', eventData);
      dispatch({ 
        type: 'events/CREATE_EVENT_SUCCESS', 
        payload: response.data 
      });
      return response.data;
    } catch (error) {
      dispatch({ 
        type: 'events/CREATE_EVENT_FAILURE', 
        payload: error.message 
      });
      throw error;
    }
  }, [dispatch]);
  
  return {
    fetchEvents,
    createEvent
  };
};
```

  }

## 七、状态管理最佳实践

### 1. 状态设计原则

- **单一数据源**：所有状态集中管理，避免分散的状态管理
- **状态不可变**：使用纯函数更新状态，避免直接修改状态
- **最小化状态**：只存储必要的状态，避免冗余
- **状态与视图分离**：状态管理与UI渲染分离，提高组件复用性

### 2. 性能优化

- **使用 useCallback 缓存函数**：避免不必要的函数重新创建
- **使用 useMemo 缓存计算结果**：避免不必要的重复计算
- **合理拆分 Context**：将不同领域的状态拆分到不同的 Context 中，避免不必要的重渲染
- **使用 React.memo 优化组件**：避免不必要的组件重渲染

### 3. 错误处理

- **统一的错误处理机制**：在 Reducer 中统一处理错误状态
- **错误边界**：使用 React 错误边界捕获组件渲染错误
- **用户友好的错误提示**：将错误信息以用户友好的方式展示给用户

### 4. 调试技巧

- **使用 React DevTools**：查看组件树和状态变化
- **添加日志**：在关键操作处添加日志，便于调试
- **使用 Redux DevTools Extension**：如果使用 Redux，可以使用其调试工具
- **状态快照**：定期保存状态快照，便于回溯问题
