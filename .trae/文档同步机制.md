## Git Hooks 配置

### Pre-commit Hook

在提交代码前检查文档是否需要更新：

```bash
#!/bin/bash
# .git/hooks/pre-commit

echo "检查文档更新状态..."

# 检查是否有代码变更
if git diff --cached --name-only | grep -E '\.(js|jsx|ts|tsx)$' > /dev/null; then
    echo "检测到代码变更，请确认是否需要更新相关文档："
    echo ""
    echo "请查看 .trae/文档同步机制.md 中的文档更新检查清单"
    echo ""
    read -p "是否已更新相关文档？(y/n) " -n 1 -r
    echo ""
    if [[ ! $REPLY =~ ^[Yy]$ ]]; then
        echo "请先更新相关文档后再提交代码"
        exit 1
    fi
fi

exit 0
```

### Commit-msg Hook

检查提交信息是否包含文档更新说明：

```bash
#!/bin/bash
# .git/hooks/commit-msg

commit_msg=$(cat $1)

# 检查是否是代码变更提交
if echo "$commit_msg" | grep -E '^(feat|fix|refactor)' > /dev/null; then
    # 检查是否包含文档更新说明
    if ! echo "$commit_msg" | grep -i 'doc' > /dev/null; then
        echo ""
        echo "⚠️  警告：代码变更可能需要更新文档"
        echo ""
        echo "如果此次提交涉及以下内容，请更新相关文档："
        echo "- API 接口变更"
        echo "- 数据模型变更"
        echo "- 组件设计变更"
        echo "- 安全策略变更"
        echo "- 性能优化变更"
        echo ""
        echo "请查看 .trae/文档同步机制.md 中的文档更新检查清单"
        echo ""
        echo "如果不需要更新文档，请在提交信息中添加 'docs: skip'"
        echo ""
    fi
fi

exit 0
```

## CI/CD 集成

### GitHub Actions 配置

在 `.github/workflows/doc-sync-check.yml` 中添加文档同步检查：

```yaml
name: 文档同步检查

on:
  pull_request:
    types: [opened, synchronize, reopened]

jobs:
  doc-sync-check:
    runs-on: ubuntu-latest
    
    steps:
    - name: 检出代码
      uses: actions/checkout@v3
      
    - name: 检查代码变更
      id: check-code-changes
      run: |
        if git diff --name-only origin/main...HEAD | grep -E '\.(js|jsx|ts|tsx)$'; then
          echo "has_code_changes=true" >> $GITHUB_OUTPUT
        else
          echo "has_code_changes=false" >> $GITHUB_OUTPUT
        fi
      
    - name: 检查文档变更
      id: check-doc-changes
      run: |
        if git diff --name-only origin/main...HEAD | grep -E '\.md$'; then
          echo "has_doc_changes=true" >> $GITHUB_OUTPUT
        else
          echo "has_doc_changes=false" >> $GITHUB_OUTPUT
        fi
      
    - name: 提示文档更新
      if: steps.check-code-changes.outputs.has_code_changes == 'true' && steps.check-doc-changes.outputs.has_doc_changes == 'false'
      run: |
        echo "⚠️  检测到代码变更但没有文档变更"
        echo ""
        echo "请确认是否需要更新以下文档："
        echo "- API接口文档.md"
        echo "- 业务流程图文档.md"
        echo "- 数据模型文档.md"
        echo "- 组件设计文档.md"
        echo "- 安全设计文档.md"
        echo "- 性能优化文档.md"
        echo ""
        echo "详细请查看 .trae/文档同步机制.md"
        exit 1
```

## 自动化脚本

### 文档一致性检查脚本

创建 `scripts/check-doc-sync.js`：

```javascript
const fs = require('fs');
const path = require('path');

const docSyncRules = {
  'backend/src/controllers/authController.js': [

  ],
  'web/src/components/': [
    '.trae/组件设计文档.md',
    '.trae/测试用例文档.md'
  ],
  'web/src/components/TaskDetail.jsx': [
    '.trae/组件设计文档.md',
    '.trae/测试用例文档.md'
  ],
  'web/src/components/PointsPanel.jsx': [
    '.trae/组件设计文档.md',
    '.trae/测试用例文档.md'
  ],
  'web/src/components/PointsForm.jsx': [
    '.trae/组件设计文档.md',
    '.trae/测试用例文档.md'
  ],
  'backend/src/middlewares/': [
    '.trae/安全设计文档.md',
    '.trae/rules/project_rules.md'
  ]
};

function checkDocSync() {
  const changedFiles = getChangedFiles();
  const warnings = [];

  for (const file of changedFiles) {
    for (const [pattern, docs] of Object.entries(docSyncRules)) {
      if (file.includes(pattern.replace('src/', ''))) {
        warnings.push({
          file,
          docs
        });
      }
    }
  }

  if (warnings.length > 0) {
    console.log('⚠️  检测到代码变更，请确认是否需要更新以下文档：\n');
    
    warnings.forEach(warning => {
      console.log(`📄 变更文件: ${warning.file}`);
      console.log('   可能需要更新的文档:');
      warning.docs.forEach(doc => {
        console.log(`   - ${doc}`);
      });
      console.log('');
    });

    console.log('详细请查看 .trae/文档同步机制.md');
  } else {
    console.log('✅ 未检测到需要更新文档的代码变更');
  }
}

function getChangedFiles() {
  const { execSync } = require('child_process');
  try {
    const output = execSync('git diff --name-only HEAD~1 HEAD', { encoding: 'utf-8' });
    return output.trim().split('\n').filter(file => file);
  } catch (error) {
    return [];
  }
}

checkDocSync();
```

## 工作流程

### 开发新功能时

1. **创建功能分支**
   ```bash
   git checkout -b feature/new-feature
   ```

2. **编写代码**
   - 实现功能代码
   - 编写测试用例

3. **检查文档更新**
   ```bash
   npm run check-doc-sync
   ```

4. **更新相关文档**
   - 根据检查结果更新相关文档
   - 在文档中记录更新日期和变更内容

5. **提交代码**
   ```bash
   git add .
   git commit -m "feat: 添加新功能

   - 实现功能描述
   - 更新相关文档：API接口文档.md, 数据模型文档.md"
   ```

6. **创建 Pull Request**
   - 在 PR 描述中列出更新的文档
   - 等待代码审查

### 修复 Bug 时

1. **创建修复分支**
   ```bash
   git checkout -b hotfix/bug-fix
   ```

2. **修复 Bug**
   - 修复代码
   - 更新测试用例

3. **检查文档更新**
   ```bash
   npm run check-doc-sync
   ```

4. **更新相关文档**（如果需要）
   - 更新 API 文档（如果接口变更）
   - 更新测试用例文档

5. **提交代码**
   ```bash
   git add .
   git commit -m "fix: 修复 Bug 描述

   - 修复内容描述
   - 更新相关文档：测试用例文档.md"
   ```

## 最佳实践

1. **及时更新文档**
   - 代码变更后立即更新相关文档
   - 不要等到发布前才批量更新文档

2. **保持文档简洁**
   - 只记录关键变更
   - 避免冗余信息

3. **使用版本控制**
   - 每次文档更新都提交到 Git
   - 使用清晰的提交信息

4. **定期审查文档**
   - 每周审查一次文档与代码的一致性
   - 及时发现和修正不一致的地方

5. **团队协作**
   - 代码审查时同时审查文档更新
   - 确保文档更新准确无误

## 常见问题

### Q: 如果忘记更新文档怎么办？

A: 可以通过以下方式补救：
1. 创建新的 commit 更新文档
2. 在 commit 信息中说明是补充文档更新
3. 在 PR 中说明情况

### Q: 是否所有代码变更都需要更新文档？

A: 不是。以下情况通常不需要更新文档：
- 纯代码重构（不改变功能）
- 性能优化（不改变接口）
- Bug 修复（不改变接口）

### Q: 如何确保文档更新的质量？

A: 建议：
1. 代码审查时同时审查文档
2. 使用文档检查工具验证格式
3. 定期进行文档审计
